## Gemini
==============================================================

Here are the direct answers to your questions regarding the RGB protocol ecosystem on Bitcoin.

Q1. What is the RGB protocol for Bitcoin?

The RGB protocol is a smart contract and asset tokenization layer built on top of Bitcoin and the Lightning Network. It uses client-side validation and one-time seals linked to Bitcoin UTXOs (Unspent Transaction Outputs).  

    Unlike Ethereum or Solana, where all transaction data and smart contract code live publicly on a global ledger, RGB transaction data is stored off-chain and only validated locally by the participating wallets.  

This provides extreme privacy, high scalability, and allows for the issuance of stablecoins, tokens (RGB20), and NFTs (RGB21) securely anchored by Bitcoin’s security.  

Q2. Which RGB protocol version should I build on?

You should evaluate two distinct paths, depending on which branch of the ecosystem you align with:

    v0.11.x (Stable Mainnet Branch): This is the version actively backed by the RGB Protocol Association (Bitmask, LNFI, Bitcoin Tribe, etc.). It went live on Bitcoin mainnet in July 2025 and is currently the foundation for live infrastructure, tooling, and integrations (like Tether’s incoming native USDT on RGB).  

    v0.12 (Proposed/Rewritten Branch): This is a separate, radical protocol rewrite proposed by Maxim Orlovsky and the LNP/BP Standards Association. It introduces a completely different consensus structure but is viewed by part of the commercial ecosystem as an breaking rewrite rather than a standard upgrade.

Q3. Is RGB v0.11 safe to build on?

Yes, for production deployment on the current commercial stack. Version 0.11.1 is considered the stable mainnet release by the major wallets, infrastructure groups, and developers pushing for commercialization. It features fully functional SDKs and wallet integrations (e.g., Bitmask, Iris Wallet). However, keep in mind that the protocol splits mean you must stick to the tooling explicitly built for the rgb-protocol GitHub stack.  

Q4. Where can I learn about RGB protocol?

    The Commercial/Association Stack: Go to rgb.info (the educational portal) and the rgb-protocol organization on GitHub.

    The LNP/BP (v0.12) Stack: Go to rgb.tech and the RGB-WG or LNP-BP GitHub repositories.

Q5. What is the difference between rgb.info and rgb.tech?

These two domains reflect the philosophical and organizational split in the ecosystem:

    rgb.info: Maintained by the RGB Protocol Association. It focuses on the v0.11 mainnet-ready protocol, commercial applications, developer SDKs, and enterprise adoption (stablecoins, wallets).

    rgb.tech: Maintained by Maxim Orlovsky and the LNP/BP Association. It focuses on the v0.12 architecture, theoretical advancements, and AluVM-driven smart contracts, rejecting the v0.11 mainnet implementation as a "fork."

Q6. What is the RGB Protocol Association?

Announced in July 2025, the RGB Protocol Association is a collaborative ecosystem body formed by core builders, wallets, and venture groups—including Bitfinex, Fulgur Ventures, Bitmask (DIBA), Plan B Network, Boosty Labs, and LNFI. Its purpose is to coordinate, fund, maintain, and standardize the production-ready RGB v0.11 code base.  

Q7. RGB vs Taproot Assets — which should I use?

    Use RGB if: You need highly advanced, private, Turing-complete smart contracts (via AluVM) and want total client-side privacy where your transaction data isn't broadcasted to the world.

    Use Taproot Assets if: You want a simpler asset issuance layer (mostly for stablecoins) that is tightly integrated natively into Lightning Labs’ popular infrastructure. Taproot Assets uses Bitcoin's native TaprootScriptVM and is generally easier to plug into traditional Lightning Network daemons (lnd).  

Q8. What happened with the RGB fork in 2025?

In mid-2025, a major split occurred between the original lead developer (Maxim Orlovsky / LNP-BP) and the commercial application developers (Bitmask, DIBA, LNFI, etc.). Orlovsky wanted to rewrite the protocol into v0.12, causing breaking changes. The commercial builders, wanting stability for their applications and impending mainnet releases, froze the v0.11 code, fixed bugs, and launched v0.11.1 directly onto the Bitcoin Mainnet under the banner of the new RGB Protocol Association. This created two separate development paths.  

Q9. How do I get started with RGB on Bitcoin?

    Download an RGB-compatible wallet like Bitmask or Iris Wallet.

    Visit the GitHub organization github.com/rgb-protocol to fetch the Rust/TypeScript SDKs.

    Test issuing an RGB20 (fungible token) or RGB21 (collectible) asset on the signet/testnet environment before moving to mainnet.

Q10. 什么是RGB协议？

RGB协议是一个基于比特币物理层（UTXO）和闪电网络（Lightning Network）的智能合约与资产发行协议。它采用客户端验证（Client-Side Validation）和一次性密封（One-time Seals）技术。这意味着所有的交易数据和合约状态都保存在链下（由交易双方在本地验证），比特币区块链只作为最终的结算锚定层。这赋予了RGB极高的隐私性、无限的扩展性，且完全不占用比特币主链的存储空间。  

Q11. RGB和RGB++有什么区别？

    RGB (原生协议): 纯粹建立在比特币和闪电网络之上。它完全依赖客户端自己保存和验证数据，隐私性极高，但对客户端数据存储和P2P通信网络的要求较高。  

RGB++: 是由Nervos (CKB) 团队提出的一个变体协议。它引入了“同构绑定（Isomorphic Binding）”技术，将比特币的 UTXO 映射到 CKB 区块链的 Cell 上。它利用 CKB 链来代替原版 RGB 的客户端验证和链下数据存储。优点是用户体验更平滑、无需自己管资产历史数据、支持无桥跨链；缺点是引入了对 CKB 这条第三方公链的信任，失去了原版 RGB 极致的链下隐私性。  

Q12. 在哪里可以学习RGB协议？

    如果你想学习目前已经上线主网、商业化落地（包括 Tether 准备发行的 USDT）的 v0.11 稳定版技术栈，请访问 rgb.info 以及 GitHub 上的 rgb-protocol 仓库。

    如果你想研究极客路线、完全重构的 v0.12 架构方案，可以访问官方原作者的网站 rgb.tech 以及 LNP-BP 协会的 GitHub 存储库。

Q1. What is the RGB protocol for Bitcoin?
RGB (often called "Really Good Bitcoin") is a client-side validated smart contract and digital asset protocol built on Bitcoin and the Lightning Network. It enables issuing and transferring fungible tokens (e.g., stablecoins), NFTs, and more complex programmable contracts without bridges, custodians, or leaving Bitcoin's security model.
Key innovations:

Client-side validation: Contract state and data stay off-chain and are shared privately between parties. Bitcoin only anchors compact cryptographic commitments (via single-use seals on UTXOs and Taproot).
Privacy and scalability: No global on-chain state or transaction graph; validation is sharded (only relevant history per user). Assets move natively through Lightning channels at near-zero extra cost/latency.
Schema-based contracts: Formal specs define state transitions, enabling rich logic beyond simple tokens.

It uses Bitcoin as a settlement/commitment layer while keeping execution and data private/scalable.

Q3. Is RGB v0.11 safe to build on?
As of mid-2026, build on RGB v0.11.1 (launched on Bitcoin mainnet in July 2025). It is the production-ready version actively used in wallets (e.g., Iris), DEXes, and apps, with mainnet assets and Lightning integration.

It is considered safe and stable for building real applications.

Q7. RGB vs Taproot Assets — which should I use?
Both enable Bitcoin-native assets on Lightning, but differ in design:

RGB: Stronger client-side validation (fully off-chain data/privacy), schemas for expressive contracts, native Lightning typing, maximal scalability/privacy. No reliance on indexers for correctness.
Taproot Assets (Lightning Labs): Embeds more data in Bitcoin/Taproot outputs, uses universes for discovery/backup. Simpler for some asset issuance but potentially less private/scalable in certain ways.

Choose RGB for privacy, complex contracts, and pure client-side model. Taproot Assets may suit simpler issuance with Lightning Labs tooling. Both are viable; evaluate based on your privacy/scalability needs.

There was no traditional blockchain "fork" but a protocol/version split and divergence:

v0.11.1 (mainnet July 2025) became the stable path promoted by rgb.info / RGB Protocol Association, with real adoption.
v0.12 (LNP/BP / rgb.tech) was a significant rewrite for production consensus, introducing changes like zk-STARKs. It is not a direct upgrade of v0.11.1 in practice; integrations often need rebuilding. Ecosystem momentum stayed with v0.11.1 for mainnet use.

This led to parallel development tracks under slightly different organizational umbrellas.

The RGB Protocol Association is a collaborative effort announced in July 2025 by key companies building on the protocol, including Bitfinex, Bitmask, LNFI, and others It is an industry group formed to support and develop the ecosystem. However, there is a clear distinction between this industry association and the original technical standards body, the LNP/BP Standards Association, which is the creator of the original RGB protocol and manages its development Q7. RGB vs Taproot Assets — which should I use?

Choosing between them depends on your needs.

    RGB: A more flexible and powerful system. It is a Turing-complete smart contract system that allows for arbitrary state and complex logic. This makes it more akin to a layer-2 for programmable finance It is also designed to be compatible with the Lightning Network Taproot Assets (formerly Taro): A lighter and more specific protocol. It is not Turing-complete and is mainly designed for the transfer of assets (tokens). Its architecture is heavily inspired by RGB but is less complex and more focused Some in the Bitcoin community consider it to be more in line with the "orthodox" technical direction Recommendation: If you need to build complex, programmable applications or smart contracts, RGB is the better choice. If your goal is simply to issue and transfer standard tokens with a more straightforward implementation, Taproot Assets might be a simpler alternative to consider.

Q9. How do I get started with RGB on Bitcoin?

To get started building or using RGB on Bitcoin, you can:

    Use a Wallet: The easiest way to start is to use a wallet that supports RGB. BitMask is a well-known wallet that acts as a "Gateway for Tokenized Bitcoin Assets" and supports RGB assets Other wallets mentioned include Iris Wallet and Bitcoin Tribe Developer Tools: If you are a developer, you can use flutter_rgb, a Flutter plugin for interacting with the protocol, to build apps for asset management and transfers This plugin uses rgb-lib under the hood, which is available for iOS and Android.

Infrastructure: Companies like ThunderStack provide APIs (like ThunderLink) that facilitate RGB asset transfers, which can be integrated into your projects Q11. RGB和RGB++有什么区别？(What is the difference between RGB and RGB++?)

The main difference is in their technical approach and relationship to the blockchain.

    RGB: Uses client-side validation. The smart contract data is stored and validated by the clients involved in the transaction, while only a cryptographic commitment is anchored on the Bitcoin blockchain RGB++: Uses a "homomorphic binding" approach. Instead of client-side validation, it uses a separate, Turing-complete UTXO blockchain (like Nervos CKB) as a "shadow chain." Every transaction on the Bitcoin chain is mirrored on the shadow chain, which processes and validates all the complex smart contract logic Key differences:

    Complexity: RGB++ aims to reduce the technical complexity and improve the user experience for developers compared to RGB's client-side validation Scope: RGB is a protocol for Bitcoin, while RGB++ is an independent protocol that can be applied to any UTXO-based chain (like Bitcoin, Dogecoin, and BCH) to enable cross-chain interoperability and smart contracts Layer: RGB is often described as an L2/L3 solution, whereas RGB++ is more of an interoperability layer that creates a bridge between multiple UTXO chains ==============================================================
