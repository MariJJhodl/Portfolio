## English Q&As

### Q1. What is the RGB protocol for Bitcoin?

**RGB** is a smart contract and asset issuance protocol built on top of Bitcoin and the Lightning Network. Unlike Ethereum, where smart contracts run globally on-chain, RGB uses **client-side validation**:

* **Off-chain data:** All contract data and history are kept privately off-chain by the users involved.
* **On-chain commitments:** It uses Bitcoin’s UTXOs as **"single-use seals"**. To transfer an asset, you spend a specific Bitcoin UTXO and commit to the new state transition inside that Bitcoin transaction (using Taproot/OP_RETURN).
* This provides extreme scalability, privacy (no transaction graph is visible on-chain), and full compatibility with the Lightning Network.

---

### Q2. Which RGB protocol version should I build on?

You should build on the **v0.11 branch (specifically v0.11.1)** if you are looking for production-ready mainnet development.

* **v0.11.1** is the version adopted by major ecosystem players (such as Tether for native USDT, BitMask, and Iris Wallet) for mainnet deployment.
* There is an ongoing transition/proposal for a **v0.12** rewrite (which aims to introduce zk-STARKs and compress history), but v0.11.1 remains the current stable, active standard for deployment.

---

### Q3. Is RGB v0.11 safe to build on?

**Yes**, relative to the rest of the RGB ecosystem. Version v0.11.1 reached mainnet-readiness in **July 2025** and has undergone extensive security testing and developer integration. It is the version officially backed by the Swiss-based **RGB Protocol Association** for immediate application deployment. However, as with any cutting-edge cryptographic protocol, standard smart contract and client-side implementation risks apply.

---

### Q4. Where can I learn about RGB protocol?

You can access several high-quality official resources:

* **Educational Portal:** [rgb.info](https://rgb.info)
* **Technical Documentation:** [docs.rgb.info](https://docs.rgb.info/)
* **Specifications & FAQ:** [rgb.tech](https://rgb.tech) and [wtf.rgb.tech](https://wtf.rgb.tech)
* **GitHub Organizations:** `github.com/rgb-protocol` (for v0.11 maintenance) and `github.com/rgb-wg` (for v0.12/LNP-BP standards).

---

### Q5. What is the difference between rgb.info and rgb.tech?

They represent the two primary developer tracks within the RGB ecosystem, which became distinct during the 2025 organizational split:

* **rgb.info:** Maintained by the **RGB Protocol Association** (the `rgb-protocol` GitHub group). It focuses on the stable, production-ready **v0.11.1** protocol branch, offering documentation, sandboxes, and developer tools aimed at immediate mainnet deployment.
* **rgb.tech:** Maintained by the **LNP/BP Standards Association** and the **RGB Consortium** (the `rgb-wg` GitHub group led by Dr. Maxim Orlovsky). It focuses on the experimental and future-looking **v0.12** protocol specification and its corresponding core libraries.

---

### Q6. What is the RGB Protocol Association?

Established in Switzerland in **July 2025**, the **RGB Protocol Association** is a Swiss non-profit foundation formed to accelerate the practical development and adoption of the RGB protocol.

* Its members include prominent ecosystem actors like **Bitfinex, Fulgur Ventures, DIBA (BitMask), Plan ₿ Network, and Boosty Labs**.
* The Association focuses on coordinating financial grants, sponsorships, standardizing the **v0.11.1** codebase, and helping companies natively integrate RGB assets onto Bitcoin.

---

### Q7. RGB vs Taproot Assets — which should I use?

The choice depends on your specific product requirements:

| Feature | RGB Protocol | Taproot Assets (Lightning Labs) |
| --- | --- | --- |
| **Primary Use Case** | Complex, private, Turing-complete smart contracts, DeFi, and tokens. | Simple asset issuance (stablecoins, memecoins) optimized for Lightning. |
| **Privacy** | **High** (Client-side validation; zero public transaction graph). | **Medium** (Relies on public "Universe" servers to index metadata). |
| **Expressiveness** | High (Supports complex logic via AluVM). | Low (Limited to simple transfers and issuance). |
| **Status** | Multi-wallet ecosystem (Iris, BitMask, MyCitadel). | Heavily integrated into the official Lightning Labs stack. |

> **Recommendation:** Use **Taproot Assets** if you want a simpler, out-of-the-box pipeline specifically for moving stablecoins over the standard Lightning Network. Use **RGB** if you require advanced smart contract programmability, absolute privacy, or want to build complex DeFi applications.

---

### Q8. What happened with the RGB fork in 2025?

In mid-2025, a divergence in development philosophy split the RGB community:

1. **The v0.11.1 Maintainers:** Led by major industry integrators (who formed the *RGB Protocol Association*). They decided to freeze and refine **v0.11.1** as a stable, production-ready standard to deploy tokens (like Tether) on mainnet immediately.
2. **The LNP/BP Association (v0.12):** Led by Dr. Maxim Orlovsky, who pushed for a significant protocol rewrite (**v0.12**) introducing zk-STARKs.

This resulted in a friendly administrative split. Instead of a hard fork of the Bitcoin blockchain, it was an **organizational and codebase split**—one focusing on immediate mainnet utility (v0.11.1) and the other on future R&D (v0.12).

2. **Set up a Sandbox:** Use the [rgb-sandbox](https://www.google.com/search?q=https://github.com/rgb-protocol/rgb-sandbox) repository to run a local node and test CLI commands.
3. **Read the Schema:** Learn how to write or issue tokens using ready-made templates like **RGB-20** (fungible tokens) or **RGB-21** (NFTs).

## Chinese Q&As (中文解答)

### Q10. 什么是RGB协议？

**RGB协议**是基于比特币（Bitcoin）和闪电网络（Lightning Network）的**智能合约与资产发行协议**。

* **客户端验证 (Client-side Validation)：** 与以太坊等将所有合约数据存在链上的网络不同，RGB的数据完全保存在链下（由交易双方保管）。
* **一次性密封 (Single-use Seals)：** RGB借用比特币的 UTXO（未花费交易输出）作为“密封条”。当你花费该 UTXO 时，就相当于打开了密封，并在对应的比特币交易中写入状态转换证明（Commitment）。
* **优势：** 极高的隐私性（链上看不出任何代币交易痕迹）、几乎无限的扩展性，且原生支持闪电网络。

### Q11. RGB和RGB++有什么区别？

虽然名字相似，但两者的架构和底层逻辑有很大不同：

| 特性 | RGB 协议 | RGB++ 协议 |
| --- | --- | --- |
| **底层代币状态** | 完全保存在客户端（链下），用户需自行保管历史证明。 | 通过“同构绑定”映射到 **Nervos CKB** 链上的 Cell 中。 |
| **数据可用性 (DA)** | 用户点对点传输和验证历史数据，存在数据丢失风险。 | CKB 链充当了数据托管和验证层，用户无需自行保存历史证明。 |
| **交互性** | 需要接收方在线合作完成交易。 | 支持非交互式转账、折叠交易以及无主合约。 |
| **安全性** | 完全继承比特币 PoW 安全性。 | 依赖 CKB 链与比特币 UTXO 的绑定和 CKB 的共识安全。 |

**Q1. What is the RGB protocol for Bitcoin?**

RGB is a protocol for issuing and transferring digital assets (tokens, NFTs, stablecoins, etc.) and running private, scalable smart contracts on Bitcoin and the Lightning Network. It uses **client-side validation**: contract data and state transitions stay off-chain and are shared privately between parties, while Bitcoin's blockchain serves only as a secure commitment/anchoring layer via single-use seals on UTXOs. This keeps everything private, lightweight (no on-chain bloat), and fully secured by Bitcoin's proof-of-work.

Assets flow natively through Lightning channels (no bridges or wrappers), enabling fast, low-cost transfers. It supports expressive schemas for complex contracts (beyond simple tokens) while preserving Bitcoin's security model.

**Q2. Which RGB protocol version should I build on?**

Build on the latest stable/mainnet version promoted by official sources (e.g., **RGB v0.11.1** on Bitcoin mainnet as of mid-2025 launches, or newer like v0.12 where available and audited). However, there were warnings about certain forks/modifications of v0.11 consensus code. Stick to official, audited implementations from trusted repos (RGB-WG or rgb-protocol) and follow security notices. Newer versions (e.g., v0.12 with zk-STARK improvements) may offer further enhancements.

### Q1. What is the RGB protocol for Bitcoin?
RGB is an open-source protocol for issuing and managing digital assets (like tokens and NFTs) and smart contracts on the Bitcoin and Lightning Network . It aims to enhance Bitcoin's capabilities for programmability, scalability, and privacy .

It achieves this through a "client-side validation" architecture . Instead of storing all transaction data on the Bitcoin blockchain (which is expensive and slow), RGB transactions are validated off-chain by the parties involved in the transfer . The Bitcoin blockchain is used primarily as a "commitment layer," where a small piece of cryptographic data (a commitment) is embedded in a regular Bitcoin transaction to anchor and secure the off-chain RGB state .

This approach uses a concept called "single-use seals," where a Bitcoin UTXO (Unspent Transaction Output) acts as a seal. When this UTXO is spent, it "closes the seal" and validates the associated off-chain state change .
