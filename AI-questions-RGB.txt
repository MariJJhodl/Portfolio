Q1. What is the RGB protocol for Bitcoin?

RGB is a smart contract and asset issuance protocol built on top of Bitcoin
and Lightning Network. It allows users to issue and manage tokens (like
stablecoins, NFTs, or other digital assets) without changing Bitcoin's base
layer. RGB leverages client-side validation, meaning most of the heavy logic
happens off-chain while the Bitcoin blockchain is used for settlement and
security, keeping privacy and scalability high.

---

Q2. Which RGB protocol version should I build on?

As of now, the latest stable version of RGB is generally recommended for new
projects. RGB uses semantic versioning, so minor versions like v0.11 might be
stable, but you should always check:
- RGB.tech releases for the current stable version
- Community channels like the RGB Discord or mailing lists for recommendations
  on production readiness

In short: build on the latest stable release unless you have a specific reason
to use an older one.

Q3. Is RGB v0.11 safe to build on?

v0.11 was considered stable, but with caveats:
- Some advanced features or APIs may still be experimental
- Security audits should be reviewed before using it in production
- The protocol evolves rapidly, so newer versions often fix issues or add
  better developer ergonomics

If you're building something that handles real value, it's generally safer to
use the latest audited release.

Q7. RGB vs Taproot Assets — which should I use?

Rule of thumb:

Q10. 什么是RGB协议？

RGB is a smart contract and asset protocol built on Bitcoin.

In simple terms: it lets you create and transfer assets (tokens, stablecoins,
NFTs) without putting all the data on the blockchain.

Key ideas:
- Client-side validation: most contract logic and data are handled off-chain
  by users
- Bitcoin as a security anchor: RGB ties asset ownership to Bitcoin UTXOs
- High privacy: transaction details are not publicly broadcast
- Scalability: since data isn't stored on-chain, it avoids congestion

One-line summary: RGB = off-chain smart contracts secured by Bitcoin

Q11. RGB和RGB++有什么区别？

RGB++ (RGB Plus Plus) is an evolution or extension approach built on top of
RGB concepts, aiming to improve usability and adoption.

RGB (original design):
- Very privacy-focused and decentralized
- Fully based on client-side validation
- Downsides: hard to build with, poor UX, complex state management,
  difficult for wallets and apps to integrate

RGB++:
- Focuses on practical usability
- Improves developer experience, wallet compatibility, state synchronization
- May introduce trade-offs: slightly less "pure" than RGB, some additional
  infrastructure or assumptions

Simple comparison:
- RGB = more pure, private, but complex
- RGB++ = more practical, easier to use, better UX

## Gemini

Q1. What is the RGB protocol for Bitcoin?

RGB is a scalable and confidential smart contract system for Bitcoin and the
Lightning Network. It operates on the principle of client-side validation,
meaning that contract data is not stored on the Bitcoin blockchain. Instead,
Bitcoin is used only as a "commitment layer" through single-use seals (linked
to UTXOs) to prevent double-spending. This allows for complex smart contracts
and asset issuance (like stablecoins or NFTs) with high privacy and
near-infinite scalability.

---

Q2. Which RGB protocol version should I build on?

As of early 2026, you should build on RGB v0.11 (or the latest stable point
release in the v0.11 series).
- v0.10 was the first major "mainnet-ready" release.
- v0.11 introduced significant improvements in contract modularity, AluVM
  (the virtual machine) stability, and better integration with the Lightning
  Network via the Bifrost protocol.

---

Q3. Is RGB v0.11 safe to build on?

Yes, for development and controlled production. While v0.11 is considered
stable and feature-complete for most use cases, the "safety" depends on your
implementation. The consensus rules are now largely ossified, but because
validation happens client-side, you are responsible for data availability
(storing your own "consignment" files). If you lose your off-chain data,
you lose access to the assets.

---

Q4. Where can I learn about RGB protocol?

The primary resources are:
- Official Documentation: rgb.tech (technical specs and guides)
- Developer Portal: blueprint.rgb.network (for practical integration)
- GitHub: The LNP/BP Standards Association repository for the latest code
- Community: The "RGB Tutorials" YouTube channel and various Telegram/Matrix
  developer groups

---

Q5. What is the difference between rgb.info and rgb.tech?

- rgb.tech: The primary technical hub maintained by the LNP/BP Standards
  Association. It focuses on the core protocol, AluVM, and standard libraries.
- rgb.info: Historically used as a community-facing landing page for general
  information and ecosystem news. Note: In 2026, most traffic has consolidated
  toward rgb.tech for technical accuracy.

---

Q6. What is the RGB Protocol Association?

It is a non-profit entity (often associated with or functioning alongside the
LNP/BP Standards Association) dedicated to the promotion, funding, and
governance of the RGB standards. Its goal is to ensure the protocol remains
open-source and to support developers building the "BiFi" (Bitcoin Finance)
ecosystem.

---

Q7. RGB vs Taproot Assets — which should I use?

Feature          | RGB                            | Taproot Assets (Lightning Labs)
-----------------|--------------------------------|--------------------------------
Logic            | Complex Smart Contracts (AluVM)| Primarily Asset Issuance/Transfers
Privacy          | High (Zero-Knowledge proofs)   | Good (Metadata hidden, less granular)
Availability     | Client-side (User-managed)     | Universe Servers (Semi-federated)
Best For         | DeFi, DAO, complex logic       | Stablecoins on Lightning (lnd-centric)

---

Q8. What happened with the RGB fork in 2025?

In mid-2025, a philosophical "fork" occurred regarding data availability.
- One faction (Standard RGB) maintained that users must stay sovereign over
  their own data.
- The other faction pushed for RGB++, which uses a different blockchain (like
  Nervos/CKB) as an "Isomorphic Binding" layer to handle data availability
  and make transactions non-interactive.

This wasn't a "split" of the Bitcoin network, but a divergence in how the
off-chain data is handled.

---

Q9. How do I get started with RGB on Bitcoin?

1. Download a Wallet: use an RGB-compatible wallet like Iris or Bitmask.
2. Run a Node: install rgb-node to interact with the protocol directly via CLI.
3. Use an SDK: if you are a dev, use the RGB Lib (Rust/TS) to issue your first
   testnet asset.
4. Join the Dev Calls: the LNP/BP Association holds regular calls for technical
   onboarding.

## Perplexity
==============================================================

Q1. What is the RGB protocol for Bitcoin?

RGB is a set of open-source smart-contract and asset-issuance protocols that
use Bitcoin only as a commitment layer, while contract data and validation
happen off-chain on clients ("client-side validation"). This design aims for
scalable, private assets and complex contracts on Bitcoin and Lightning without
bloating the blockchain.

---

Q2. Which RGB protocol version should I build on?

As of mid-2025, the RGB contracts consensus was released as a production-ready
v0.12 for mainnet and testnet deployments, and that is the version the
Association explicitly positions as stable for issuers and developers. For new
projects, you generally want to target this production consensus (v0.12) and
keep an eye on the official docs and repositories for any minor, non-breaking
updates.

---

Q3. Is RGB v0.11 safe to build on?

v0.11 went through multiple betas with feature-freeze, stable APIs, extensive
end-to-end tests, and refactoring of consensus-critical code to reduce attack
surface, and it was explicitly marked as an audit reference point. However, it
was still a beta line, and the maintainers positioned v0.12 as the final,
production-ready consensus, so new mainnet projects should prefer v0.12 while
treating v0.11 mainly as a stepping stone or for legacy work.

---

Q4. Where can I learn about RGB protocol?

Key starting points include the official learning section and docs at rgb.tech
(whitepaper, specifications, API docs, and tutorials for command-line tools and
node software). Community and curated resources like rgbfaq.com, the RGB
blueprint site, and the "awesome-rgb" GitHub list collect FAQs, standards, and
ecosystem projects in one place.

---

Q5. What is the difference between rgb.info and rgb.tech?

rgb.tech is the official site of the LNP/BP Association for RGB, providing
protocol specs, developer docs, blog posts on releases (such as the v0.11
betas), and onboarding material. rgb.info (not in the primary official doc set)
is more of an information/portal site; for authoritative technical and roadmap
information, rgb.tech and the associated GitHub orgs are the canonical
references.

---

Q6. What is the RGB Protocol Association?

The RGB protocol is mainly led and standardized by the LNP/BP Standards
Association (often just called the LNP/BP Association), which publishes the
specs and releases, including the RGB v0.11 betas and the v0.12 production
consensus. This body coordinates development of the protocol stack, maintains
key libraries and documentation, and announces consensus-critical milestones
for developers and issuers.

---

## Grok

Q1. What is the RGB protocol for Bitcoin?

RGB is a client-side validated smart contract system native to Bitcoin and the
Lightning Network. It allows issuing and transferring digital assets, rights,
NFTs, stablecoins, and full programmable contracts (DeFi, DAOs, etc.) while
keeping all contract data and history off-chain. Bitcoin serves only as a
cryptographic commitment layer (via Taproot outputs) to prevent double-spending.
No on-chain data bloat, no extra validators or federations, and full privacy via
zero-knowledge proofs for state history. It is highly scalable (sharded by
design) and Lightning-native for instant atomic swaps.

---

Q2. Which RGB protocol version should I build on?

Build exclusively on the official v0.12 (consensus released July 2025) and any
later updates from the RGB-WG GitHub organization. This is the audited,
peer-reviewed lineage maintained by the RGB Consortium / LNP/BP Standards
Association. Always check dependencies with `cargo tree -i rgb-consensus` to
ensure you are not pulling in any forked code. The latest CLI/Node releases are
available at https://rgb.tech/install and https://github.com/RGB-WG/rgb/releases/latest.

---

Q3. Is RGB v0.11 safe to build on?

The original v0.11 betas (2024) are now outdated and no longer recommended for
production.

The version marketed as "RGB v0.11.1" (released July 2025) is an unauthorized
fork by Bitfinex. It contains dangerous consensus changes (removal of
smart-contracting features, no zk support, extremely poor code quality, almost
zero tests). The official team issued a security notice on 18 July 2025
explicitly warning against any use in production — it is unsafe and can lead to
asset loss. Do not use it.

---

Official resources (all free):
- https://rgb.tech/learn/ (tutorials, specs, API docs)
- Blackpaper & whitepaper: https://blackpaper.rgb.tech
- Full documentation: https://rgb.tech/docs and https://docs.rgb.info
- FAQ + videos: https://www.rgbfaq.com and LNP-BP YouTube channel
- GitHub (specs + code): https://github.com/RGB-WG
- Issuer & power-user guides: https://rgb.tech/power-user

Start with the "Learn" and "Program" sections on rgb.tech, then install the
CLI to experiment.

---

Q5. What is the difference between rgb.info and rgb.tech?

Both sites belong to the same official RGB project.
- rgb.tech — the main developer & community hub (blog, releases, install
  guides, programming tutorials, wallets, integration docs, Contractum updates).
  Maintained by the RGB Consortium.
- rgb.info — a clean, user-friendly explanatory / marketing site focused on
  "What is RGB?", benefits, use cases, and high-level overviews.

They complement each other; use rgb.tech for building and rgb.info for quick
introductions.

---

Q6. What is the RGB Protocol Association?

A non-profit foundation registered in Switzerland, launched on 14 July 2025.
Its mission is to accelerate RGB adoption through grants, open-source
infrastructure, education, and global coordination. It is politically and
financially independent and works alongside (but is distinct from) the LNP/BP
Standards Association and RGB Consortium. It has already supported mainnet
launches and major integrations (e.g., Tether USD₮).
Website: https://rgbprotocol.org/

Q7. RGB vs Taproot Assets — which should I use?

Feature                | RGB (official)                      | Taproot Assets (Lightning Labs)
-----------------------|-------------------------------------|--------------------------------
Scope                  | Full smart contracts + assets       | Primarily assets & stablecoins
Validation             | Pure client-side (max privacy)      | Client-side + optional Universe
Programmability        | Turing-complete (AluVM/Contractum)  | Limited (asset transfers)
Scalability & Privacy  | Highest (zero-knowledge history)    | Very good
Lightning integration  | Native & advanced                   | Native
Maturity (2026)        | v0.12 production-ready              | Production-ready

Use RGB for general-purpose smart contracts, DeFi, or maximum privacy/scalability.
Use Taproot Assets for simple, fast asset issuance (especially stablecoins) with
easier discovery. Many projects run both or bridge them.

---

Q8. What happened with the RGB fork in 2025?

In July 2025 Bitfinex released a heavily modified fork of the old v0.11 codebase
and marketed it as "RGB v0.11.1", claiming a mainnet launch. The fork removed
smart-contract functionality, introduced consensus-breaking changes, had terrible
code quality, and zero test coverage. The official RGB team published a security
notice on 18 July 2025 warning the entire ecosystem not to use it and directing
everyone to the official v0.12 instead. Some projects briefly adopted the fork,
but the consensus view is to treat any assets issued on it with extreme caution.
The incident led directly to the creation of the RGB Protocol Association for
better governance.

---

1. Install the official RGB CLI + Node: https://rgb.tech/install
2. Run a local Bitcoin node (or use a testnet/regtest).
3. Issue your first asset or contract via the CLI or issuer guides.
4. For development:
   - Simple contracts → Rust macros
   - Advanced → AluVM / upcoming Contractum language
   - Integration → JSON SDKs
5. Test on regtest, then move to mainnet with real UTXOs.
6. Join the community: RGB Consortium Discord/GitHub and the Association channels.
   Full step-by-step tutorials are at rgb.tech/docs.

Q10. 什么是RGB协议？

RGB协议是比特币上的可扩展、隐私保护型智能合约系统，基于客户端验证（Client-Side
Validation）和一次性密封（Single-Use Seals）技术。它允许用户发行和管理资产（如代
币、NFT）而无需依赖链上全局状态，所有数据存储在链下，仅通过比特币交易锚定所有权。

---

Q11. RGB和RGB++有什么区别？

- RGB：原生协议，依赖比特币脚本（如P2C、P2TR）和客户端验证。隐私性强，但开发门槛
  较高。
- RGB++：基于RGB的扩展方案，通过同构绑定将RGB状态提交到比特币UTXO上，兼容CKB
  （Nervos）等链的验证。简化了开发流程，支持跨链交互，牺牲部分隐私换取易用性。

附加常见问题：

  版本选择: v0.11为早期测试版本，不建议生产环境使用。推荐最新稳定版（如v1.0+）。
  安全性: v0.11存在风险，建议等待审计完成的版本。
  2025年分叉事件: 社区对RGB技术路线的分歧，形成RGB Core（主网）和RGB Lite（简化版）
  两个分支，核心功能兼容。
